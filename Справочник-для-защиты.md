# 📘 NewsAggregator — полный справочник для защиты

> Документ для подготовки к защите проекта: архитектура, стек, схема данных, все модули, REST API и разбор «каверзных» вопросов.

---

## 1. ОБЩАЯ СУТЬ

**NewsAggregator** — веб-система автоматического сбора, классификации и отображения новостей из российских СМИ. Раз в 30 минут фоновый процесс обходит источники, извлекает свежие статьи, автоматически относит их к рубрикам (политика, экономика, спорт и т.д.), сохраняет в базу SQLite и отдаёт пользователям через REST API. Пользователи имеют аккаунты (JWT-авторизацию), получают персональные рекомендации, видят фильтры, поиск, курсы валют и тёмную/светлую тему.

**Ценность**: пользователь не ходит по 5 сайтам — приложение само агрегирует, дедуплицирует, рубрицирует и рекомендует.

## 2. СТРУКТУРА РЕШЕНИЯ (архитектура)

Трёхслойная архитектура (N-tier) с чётким разделением ответственности:

| Проект | Роль | Что содержит |
|---|---|---|
| **NewsAggregator.Core** | Доменный слой | Сущности (Entity), DTO, интерфейсы. Никаких зависимостей от инфраструктуры и Web. |
| **NewsAggregator.Infrastructure** | Слой данных/бизнес-логики | Реализации сервисов, EF Core DbContext, миграции, фоновые службы, парсер, классификатор, почта, валюты. Зависит только от Core. |
| **NewsAggregator.WebAPI** | Презентационный слой | Контроллеры, Middleware, DI, JWT, Swagger, Serilog. Зависит от Core (интерфейсы) и Infrastructure (реализации). |
| **news-client/** | Frontend SPA | React 19 + TypeScript + Vite. |

**Правило зависимостей**: зависимости всегда направлены «внутрь» — Core ничего не знает о существовании остальных. WebAPI регистрирует в DI интерфейсы Core + реализации Infrastructure (Program.cs:44–49).

## 4. БАЗА ДАННЫХ

**СУБД**: SQLite (файл `newsaggregator.db`). Плюсы: не нужен отдельный сервер, портативно, достаточно для сотен новостей, легко деплоить и тестировать.

### Сущности (`Core/Entities`)

| Сущность | Ключевые поля |

## 5. ПАРСИНГ (главный модуль)

**Файлы**: `ParserService.cs`, `BackgroundServices/NewsParserBackgroundService.cs`.

### Источники — два типа
**A. RSS (3 источника)** — `RssSource[]`:
- Lenta.ru — `https://lenta.ru/rss/`
- ТАСС — `https://tass.ru/rss/v2.xml`
- RT на русском — `https://russian.rt.com/rss`

Берётся **топ-30 статей** (`Take(30)`): title, link/guid, description, pubDate; картинка — из `<media:enclosure url=…>` или `<img src>` в описании.

**B. HTML-скрейпинг (2 источника)** — `HtmlSource[]` с регулярками:
- РБК — атрибут `data-role="title-link"` (главная страница)
- Известия — `class="node__cart__item__inside"` (заголовок внутри `<span>`)

### Дополнение картинками (`EnrichWithImagesAsync`)
У статей без превью запрашивается страница и вытаскивается мета-тег **`og:image`**. Параллельность — `SemaphoreSlim(8)`, таймаут 4 сек, ошибки не роняют парсинг (картинка остаётся null).

### Дедупликация
`HashSet<string> seenUrls` с нормализацией URL (обрезается querystring). Одна новость не попадёт дважды в одном проходе.

### Рубрикация (`ClassifierService`)
Наивный «голосовательный» классификатор: словарь `Keywords` по категориям (рус/англ). По заголовку считается количество совпадений на категорию — побеждает максимум. Результат мапится в `CategoryId` (1–13, иначе «Другое» = 13).

### Фоновый цикл (`NewsParserBackgroundService`)
`BackgroundService` → старт через 1 минуту после запуска, затем **каждые 30 минут**:
парсить → сохранять через `NewsService.SaveNewsAsync` → логировать. Внутри цикла создаётся scope (сервисы Scoped, DI не может инжектировать их напрямую в фоновую службу).

## 6. АВТОРИЗАЦИЯ И АУТЕНТИФИКАЦИЯ

**Файлы**: `AuthService.cs`, `AuthController.cs`, `Program.cs` (JWT), `AuthContext.tsx`, `api.ts`.

### Регистрация
1. Проверка занятости Email и Username (unique-индексы).
2. Первый зарегистрированный юзер получает роль **Admin** (`adminExists`), остальные — User.
3. Пароль: `BCrypt.HashPassword` (соль автоматически).

### Вход
- Находит юзера по Email → `BCrypt.Verify` хэш.
- Успех → `GenerateTokensAsync`: Access + Refresh.

### Токены
- **Access**: **JWT HS256**, 15 минут. Claims: NameIdentifier (id), Name, Email, Role. Подпись — симметричный ключ из `JwtSettings:SecretKey`.
- **Refresh**: 64 случайных байта → Base64, хранится в БД на юзере, живёт **7 дней**, ротация при каждом обновлении.

### Валидация JWT (Program.cs:57–75)
`ValidateIssuer`, `ValidateAudience`, `ValidateLifetime`, `ValidateIssuerSigningKey`, `ClockSkew = Zero`.

### Сброс пароля
1. `POST /auth/forgot-password` → одноразовый token (64 байта), срок 1 час, старые токены удаляются; письмо со ссылкой `/reset-password?token=…`.
2. **Анти-подсчёт email**: сервер всегда отвечает `Ok`, даже если email не найден.
3. `POST /auth/reset-password` → новый хэш, токен `IsUsed = true`.

### Frontend-аутентификация
- `AuthContext` держит юзера в состоянии.
- Access/Refresh в `localStorage`.
- axios-interceptor: при **401** → `/auth/refresh` → новые токены → повтор исходного запроса; при провале — очистка localStorage → `/login`.
- `PrivateRoute` закрывает `/` и `/news/:id`.
- `isAdmin` — кнопка «Обновить новости».

## 8. РЕКОМЕНДАЦИИ

`RecommendationService` (`RecommendationsController`):
1. Топ-3 категорий юзера по числу чтений из `UserReadHistory`.
2. Нет истории → **случайная подборка свежих** (до 10) для «прогрева».
3. Иначе — свежие новости топ-категорий, исключая уже прочитанные.
4. `TrackReadAsync` — фиксирует чтение и увеличивает `ViewCount`.

## 9. ВАЛЮТЫ

`CurrencyService`: бесплатный API `api.exchangerate-api.com/v4/latest/USD`, 8 валют (USD, EUR, GBP, JPY, CNY, CHF, CAD, AUD) с флагами, кэш `IMemoryCache` на **1 час**. `CurrencyBackgroundService` обновляет кэш каждый час.

## 10. ПРОКСИ КАРТИНОК (ImageProxyController)

Фронт оборачивает внешний URL картинки через `api/imageproxy?url=…`:
- SHA256-хэш URL → файл в `image-cache/`, TTL **7 дней**.
- Повторный запрос — чтение из кэша (быстро).
- Ретраны (2 попытки), обход hotlink-защиты (Referer, User-Agent).
- Определение типа по **магическим сигнатурам** (JPEG `FFD8FF`, PNG `89504E47`, GIF, WebP).

## 14. ПОТОК «КАК ВСЁ РАБОТАЕТ» (сквозной)

1. `NewsParserBackgroundService` (каждые 30 мин) → `ParserService` → новые News → `SaveNewsAsync` → SQLite.
2. Пользователь открывает `/` → лента карточек → клик по карточке → трек чтения (если залогинен) → история.
3. «Рекомендовано для вас» → топ-3 категорий по истории → свежие новости этих категорий.
4. Sidebar-категории — со счётчиками из `GET /categories`.
5. Токены: при истечении access → refresh автоматически.

## 15. «КАВЕРЗНЫЕ ВОПРОСЫ» ПРЕПОДАВАТЕЛЯ — ОТВЕТЫ

**— Почему SQLite, а не PostgreSQL?**
Проект небольшой (сотни новостей), нужен ноль-конфиг: не нужен сервер БД, один переносимый файл. Плюс EF Core унифицирует доступ — при росте просто меняем ConnectionString на Postgres (драйвер Npgsql).

**— Как решаются дубли новостей?**
Уникальный индекс на `News.Url` (уровень БД) + `HashSet<string> seenUrls` в парсере + в `SaveNewsAsync` существующая запись не дублируется (только дополняет ImageUrl при необходимости).

**— Что если источник недоступен?**
Каждый источник в `try/catch` (ParserService:65–95): ошибка логируется, парсинг остальных продолжается. Фоновая задача тоже ловит исключения.

**— Почему BCrypt, а не MD5/SHA?**
BCrypt — солёная функция с вычислительной «дорогостью», устойчива к оффлайн-подбору. Пароли не хранятся в обратимом виде.

**— Зачем Access + Refresh токены?**
Access живёт 15 минут — компрометация даёт короткое окно. Refresh хранится в БД, живёт 7 дней и ротируется при каждом обновлении.

**— Как распределяются категории?**
Словарный классификатор с подсчётом совпадений по заголовку. Без ML-моделей — быстро и достаточно для задачи.

**— Зачем фоновому сервису scope вручную?**
Сервисы зарегистрированы как Scoped; `BackgroundService` живёт всё время приложения и должен сам создавать scope для доступа к БД.

**— Что с картинками РБК/ТАСС?**
В нашей сети CDN РБК (s0–s4.rbk.ru) недоступен на уровне TLS — все реализации (curl, .NET) дают `SEC_E_INVALID_TOKEN`, это внешняя блокировка. ТАСС отдаёт JS-challenge (servicepipe.tech), страницы статей через простой HTTP не отдаются. Код прокси работает — Lenta/RT/Известия дают 200. Карточка без фото просто не рисует рамку (последняя правка).

**— Сколько новостей собрано?**
~238 (по актуальной БД), с картинками ~183.
